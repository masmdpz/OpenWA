# OpenWA on Android for free (Termux)

This is a **self-hosted, no-monthly-fee** option for an ARM64 Android phone when no VPS or Docker host is available. The phone itself runs OpenWA. It is not cloud hosting: the phone must stay powered on and connected to the internet.

## What this setup does

- Runs OpenWA inside Debian using Termux's `proot-distro`; no Android root and no Docker are required.
- Uses Node.js 24.22.2, which satisfies this repository's Node.js `>=22.19` requirement.
- Builds the backend and dashboard on the phone.
- Keeps SQLite, Baileys pairing credentials, the generated API key, and other OpenWA state under `/opt/openwa/data` inside Termux's private app storage.
- Uses Baileys by default. Chromium is not downloaded because this setup does not use `whatsapp-web.js`.
- Uses Cloudflare Quick Tunnels for a temporary public HTTPS URL. No Cloudflare account or custom domain is needed.

## Requirements and trade-offs

- A 64-bit ARM Android device, Termux, a working internet connection, and enough free internal storage for Debian, Node dependencies, and the database.
- The first install downloads Debian, Node.js, OpenWA dependencies, and builds the dashboard. This is a substantial download/build and can be slow on a phone.
- Set Termux's Android battery usage to **Unrestricted**. For longer use, keep the phone on Wi-Fi and power. Android may still stop background processes; this is not a 24/7 uptime guarantee.
- A Quick Tunnel hostname is random and changes when the tunnel is restarted. Cloudflare documents Quick Tunnels as testing/development use, with no uptime guarantee, a 200 in-flight request limit, and no Server-Sent Events support. Do not treat this as production hosting.
- The tunnel URL is publicly reachable by anyone who has it. Protect OpenWA with its generated API key; never post that key or the URL in public.
- Removing Termux or clearing its app data removes the locally stored OpenWA database and linked-device credentials. Back up `/opt/openwa/data` before uninstalling or resetting the app.
- OpenWA is an unofficial WhatsApp client. Account restrictions are still possible. Read the warning in the repository README before linking an account.

## Install

Install Termux from one official distribution source and keep any Termux add-ons from that same source. Open Termux and run:

```bash
pkg update -y
pkg install -y curl
curl -fsSL https://raw.githubusercontent.com/masmdpz/OpenWA/main/scripts/install-termux.sh -o install-openwa.sh
bash install-openwa.sh
```

The installer adds these Termux commands:

| Command       | Purpose                                                      |
| ------------- | ------------------------------------------------------------ |
| `openwa`        | Starts the OpenWA API and dashboard                          |
| `openwa-tunnel` | Creates a temporary HTTPS URL                                |
| `openwa-key`    | Prints the generated admin API key                           |
| `openwa-update` | Pulls the latest main, reinstalls dependencies, and rebuilds |

## Start OpenWA

1. Run `openwa` in a Termux session. Keep this session running.
2. Open a second Termux session and run `openwa-tunnel`.
3. Copy the `https://….trycloudflare.com` hostname printed by Cloudflare.
4. Wait for the first OpenWA boot to finish. In another Termux session, run `openwa-key` and use that key to sign in to the dashboard.
5. Create a session in the dashboard. OpenWA's default engine is Baileys. For phone-number linking, follow [Session Phone-Number Pairing](./examples/session-phone-number-pairing.md).

The admin key is generated by OpenWA and stored locally at `/opt/openwa/data/.api-key` inside Debian. The installer does not put credentials in GitHub.

## Update

Stop the running OpenWA process with `Ctrl+C`, then run:

```bash
openwa-update
```

Start it again with `openwa`, then restart `openwa-tunnel` to obtain a new Quick Tunnel hostname.
